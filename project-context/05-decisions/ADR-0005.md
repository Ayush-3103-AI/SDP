# ADR-0005 — Streamlit dashboard + SQLite event store, two processes

STATUS:      accepted
DATE:        2026-10-03
REVERSIBLE:  cheap

## Context
A UG team needs a dashboard quickly. The loop must never block on the UI.

## Options
1. FastAPI + JS frontend. More control, much more code.
2. OctoPrint plugin. Native, but couples us to the plugin API.
3. Streamlit app polling a SQLite (WAL) store that the loop writes to; decisions written back to the same DB.

## Decision
Option 3. One DB file per run: `runs/<run_id>/events.sqlite`. Streamlit polls every 0.5 s.

## Consequences
Free audit log for evaluation. Polling latency ≤ 1 s is acceptable because human decisions take seconds anyway. A single writer per table is enforced by schema ownership (09-interfaces §Store).
