# ADR-0004 — Safety gate as a pure, fail-closed function with four layers

STATUS:      accepted
DATE:        2026-10-03
REVERSIBLE:  costly

## Context
The deck's four-layer gate: L1 physical, L2 rate/step, L3 characterised window, L4 confidence. Must be auditable and testable without a printer.

## Options
1. Checks scattered through the orchestrator.
2. One pure function `gate(proposal, state, cause_set, cfg, now) -> GateDecision` with no I/O.

## Decision
Option 2. Per layer:
- **L1:** reject if the target is outside machine limits.
- **L2:** clip |Δ| to step_max; reject if the variable is in cooldown.
- **L3:** reject if the target is outside the characterised window.
- **L4:** routes to `apply` (auto) or `propose` (human).

Any missing or NaN state field → `escalate`. Every layer writes a human-readable reason, and these reasons are part of the explanation shown to the operator. The operator's *Modify* value is re-gated in the loop process (trust boundary).

## Consequences
Property-testable (T-0023). The deck's absolute recipes will be shown to violate L2/L3 (reported in T-0023), which is a result in its own right. Upgrade path: a convex-hull L3 if the DOE window isn't a box.
