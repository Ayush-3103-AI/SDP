# ADR-0001 — Standalone `xqi` package that reimplements the thin loop, with four run modes

STATUS:      accepted
DATE:        2026-10-03
REVERSIBLE:  cheap

## Context
The REU loop code hasn't been seen yet (T-0002). The loop itself is small: camera → YOLO → confirm → OctoPrint. Every claim (S4, S5) needs the deck's behaviour reproduced as a baseline on the same rig.

## Options
1. Fork and patch the REU code. Blocked until hand-over; unknown structure.
2. A new package that reimplements the loop, with REU parameters ported in as config. Starts now, owns every contract.

## Decision
Option 2. Modes: `baseline` (deck recipes, no gate), `gated-recipe` (deck recipes through the gate), `auto`, `advisory`. Parity with the REU loop is checked in T-0033 (same recipes, same critical behaviour).

## Consequences
Reuse REU code for the confirmation counts and OctoPrint details once received. Risk: subtle behaviour differences from REU; mitigated by the baseline-mode parity test.
