# ADR-0009 — Software-only scope; public parameter-labelled data for causability

STATUS:      proposed
DATE:        2026-10-27
REVERSIBLE:  costly (it fixes the dataset every evaluation rests on)
SUPERSEDES:  ADR-0008 (own printing campaign); charter Amendment 1 → Amendment 2

## Context
- The REU hand-over is 5,490 unlabelled frames of one print. It has no labels, no causes and no YOLO11-S
  (ADR-0008 §Context). K1 has fired for that data.
- User directive: our deliverable is the model software. Another team does the transfer to the printer.
  Out of scope: printer connection, OctoPrint/G-code transport, camera or Raspberry Pi selection, rig runs,
  and induced-defect printing.
- So causability can't come from our own printing. It needs an existing digital dataset whose images
  carry process-parameter ground truth.
- Candidate found and checked (2026-10-27):
  - Cambridge Apollo repository, "Data set for 'Generalisable 3D printing error detection and correction
    via multi-head neural networks'" (Brion & Pattinson, Nat. Commun. 13, 2022,
    doi:10.1038/s41467-022-31985-y), https://www.repository.cam.ac.uk/handle/1810/339869
  - ~1.27 M nozzle-camera images of 192 parts, each labelled with flow rate, lateral speed, Z offset, hotend
    temperature + target, bed temperature, timestamp and nozzle x/y.
  - A pre-filtered CSV covers 948,396 images.
  - Licence: the paper is CC BY 4.0. The dataset's own licence must be confirmed before use (Q1).
  - Weakness: the images are close-ups at the nozzle, not a whole-bed view, and there are no defect boxes.

## Decision (proposed)
- **D1 Scope.** In scope:
  - the cause model (causability)
  - explanation: attribution heatmap, conformal cause set, counterfactual "smallest safe change"
  - proactive early warning
  - the 4-layer safety gate on recommendations
  - the human-in-the-loop advisory loop and dashboard
  - offline evaluation
  - a documented hand-off API

  Out of scope: everything physical. The existing `Printer` protocol (xqi/printer.py) is the **hand-off
  boundary**: the other team implements it for their hardware. FakePrinter stays as our simulator. The
  OctoPrint client already built is kept as an unsupported reference, not maintained or tested on hardware.
- **D2 Cause data = CAXTON.**
  - Each print becomes a `trial`, each part a `geometry`.
  - The cause label is the deviating parameter and its direction: `flow_low/high`, `speed_low/high`,
    `nozzle_temp_low/high`, `z_offset_low/high`, or `none` when all parameters are nominal.
  - The thresholds that bin a parameter into low/good/high come from the paper's own bins [verify at the
    Phase 2 delta].
  - `bed_temp_low` and `misalignment` have no CAXTON labels. They stay detection- or rule-only.
  - A subset (~50–100 k images, stratified over all 192 parts) is downloaded and preprocessed on the GPU
    laptop. Nothing heavy runs on the dev laptop (standing instruction).
- **D3 Model shape.**
  - The cause model reads an image region and predicts the cause, image-only (ADR-0002 option 2 kept).
    Telemetry stays out of the model: the parameter values ARE the labels.
  - It runs on the frame or region the detector flags. With CAXTON there are no boxes, so training uses the
    nozzle-region image.
  - Detection is a pluggable upstream input: the YOLO wrapper takes whatever weights the integrating team
    supplies. The inherited AM_1 (1-class `defect`) is a placeholder. We do not train a defect detector
    (no box labels exist).
- **D4 Proactiveness (new module).** Per print, a running cause-probability trend raises an **early warning**
  and a proposed correction before a defect is confirmed. The human approves, modifies or rejects through
  the existing card flow, and the gate still applies. It is measured on CAXTON's timestamped parameter
  changes: time from a parameter's deviation onset to the warning, and false warnings per hour of nominal
  printing.
- **D5 Evaluation = offline, by parts.**
  - Leave-parts-out folds (ADR-0007 re-scoped: the "geometry" is the CAXTON part) over the subset.
  - The calibration split is by print.
  - The prior-based score (ADR-0002 option 1) is always reported on the same folds as the floor.
- **D6 Camera roll + inherited models.** Replay/demo feed and a domain-shift sanity check only (whole-bed
  view, different printer). Never used in training or eval splits.

## Metrics (charter Amendment 2)
| # | Metric | Threshold | Conditions |
|---|---|---|---|
| S1 | Cause top-1 accuracy | ≥ floor + 10 pp (floor = majority/prior per class), bootstrap 95 % CI | CAXTON subset, leave-parts-out |
| S2 | Conformal cause-set coverage | ≥ 0.85 at α = 0.10, mean set size ≤ 2.0 | same |
| S3 | Gate violations | 0 in 100 000 randomised cases | software property test |
| S4 | Explanation latency | cause + conformal + attribution ≤ 30 ms p95 per event (A6) | RTX 3050, offline bench |
| S5 | Proactive warning | median time-to-warning ≤ 10 s after deviation onset; ≤ 1 false warning per nominal print-hour [assumed] | CAXTON prints with mid-print parameter changes |
| S6 | Counterfactual direction | proposed Δ opposes the true deviation in ≥ 90 % of correct-cause events (NFR-007) | same folds |
| S7 | HITL study (SHOULD) | explanation ON vs OFF: correct-decision rate, CI reported | offline replay cards |

Kill criteria:
- K1′: the CAXTON licence or access fails, or no usable subset exists within 1 week. Fallback: the Kaggle
  "early detection of 3D printing issues" set (binary under-extrusion only) + priors, with S1 re-scoped.
- K2 (unchanged): leave-parts-out top-1 ≤ floor + 5 pp → the ADR-0002 option 1 pivot.
- K3: dropped (hardware is out of scope).

## Open questions (recommended answer in brackets)
- Q1 May we use public datasets beyond what the REU team left (CAXTON; CC BY 4.0 to be confirmed)? [Yes. It is
  the only cause-labelled source, and the camera roll alone cannot support causability.]
- Q2 Detector: train one, or treat detection as a pluggable input? [Pluggable input. Inherited AM_1 as a
  placeholder; the other team supplies production weights.]
- Q3 Does "proactive" mean early warning + proposed correction before the defect is confirmed, with human
  approval? [Yes, as in D4.]
- Q4 Hand-off: the `xqi` package + Printer protocol + recommendation API doc + FakePrinter? [Yes.]
- Q5 Does Dr. Meti accept CAXTON-based, leave-parts-out metrics? [Take ADR-0009 to her this week.]
