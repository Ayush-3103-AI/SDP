REU camera roll: what it is and what it's good for

Audit of the previous team's Drive folder "Camera Roll" · 2026-10-26 · relates to T-0002 item 2 (#2)

It does not unblock the critical path. The folder holds 5,490 unlabelled 1280×720 webcam stills of one print of one part, taken on 2025-04-29 between 11:20 and 17:52. It has no YOLO labels, no train/val/test split and no induction log.

T-0005 (adapter) and T-0006 (audit, K1) still need the labelled 6,454-image YOLO dataset, the induction log and best.pt. Treat this drop as T-0002 item 2: partially received.

It is still useful as a realistic replay feed and a "normal print" set for false-alarm testing. All of it is one trial, so it must never be split image by image.

Preprocessing: held until the use is chosen

If the use is replay or false-alarm testing, the steps are:

  1. Download the 1280×720 originals (about 550 MB) to data/raw/camera_roll/, which git ignores.
  2. Drop near-duplicates (h ≤ 3) and the 28 blurry frames.
  3. Optionally drop the handheld block (13:47–15:15) for a stable view.
  4. Write an index with one trial_id per row.

Resizing to imgsz 1088 happens at inference, so it is not a preprocessing step. If the team decides to label these frames, the steps are different.

Method

The folder was listed through Drive's public embed view. 256-px thumbnails of all 5,491 entries were downloaded (0 failures, 5,490 unique names). Per-frame values were computed with OpenCV: 64-bit dHash, mean grey level and Laplacian variance. Sessions were cut at gaps over 5 minutes. One contact sheet of 24 evenly spaced frames per session was reviewed by eye. Per-frame results are in the scratch file frames.csv; they can be regenerated.
