Runtime loop

Offline: how the runtime model files are made

CPU scripts run on the dev laptop; training and the fold evaluations run on the teammate's GPU laptop (docs/gpu-runs/). The three files on the right are what config/default.yaml points the runtime at.

Safety invariant. Printer commands leave only through gate(), except the critical-class estop/pause and baseline mode. The dashboard never reaches the printer; its decisions are re-gated.
Explain ≠ decide. The cause model sees only the image. Printer state enters later, in sensor flags, proposal sizing and the gate, so an explanation can't be biased by what the setpoints already are.
Off the latency path. Heatmaps run on a worker thread with their own copy of the net and their own SQLite connection, after dispatch.
