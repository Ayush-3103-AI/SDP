# T-0066 runbook: offline end-to-end HITL demo on held-out CAXTON prints (GPU laptop)
Written 2026-11-16. Needs: `models/cause/final.pt` and `models/cause/qhat.json` (SITTING-2026-11-16 steps 5–6) and the
complete `data/crops.csv`. Total ≈ 45 min, of which ≈ 25 min need a person at the dashboard.

Latency definitions (D6, proposed 2026-11-16, pending the user's approval of the 07 §7 / 09 §Store edit):
NFR-002 = frame → verdict (t_gate − t0), NFR-003 = event → card first shown (t_card − t_conf; the dashboard writes
t_card the first time it draws a card), NFR-004 = every dispatched setpoint command re-checked against the envelope.

## Steps
1. `uv run pytest tests/test_run_demo.py tests/test_store.py -q -m "slow or not slow"`
   Expected: all pass (on Windows `test_concurrent_ui_decision_during_loop_write` passes too). Time < 2 min.
2. `uv run python scripts/run_demo.py --selftest` → last line `selftest ok`. Time ≈ 1 min.
3. `uv run python scripts/run_demo.py plan`
   Expected: `planned: pA (fold i), pB (fold j), pC (fold k)`. Writes runs\demo\plan.json and one config per print.
   Run it **once**; the draw is fixed before any result is seen.
4. **Auto, unattended (≈ 15 min):** `uv run python scripts/run_demo.py run --mode auto`
   Expected: one line per print `pX auto: runs\<id>\events.sqlite`. Warnings stay PROPOSE in auto mode (07 §4 row 9).
5. **Advisory with a person (≈ 5–8 min per print).** For each planned print pX, in order:
   - Terminal 1: `uv run python scripts/run_demo.py run --mode advisory --print pX`
   - Terminal 2, as soon as terminal 1 prints its first INFO line: `uv run python -m xqi ui --run latest`, type
     your name in the sidebar. Keep the browser tab in front (NFR-003 is measured from what the dashboard draws).
   - Decide every card as you would at the printer: Apply, Modify Δ, Reject or Pause. On at least one card use
     **Modify** with a value larger than the step limit, so the gate clips it.
   - Screenshots (Win+Shift+S, save as PNG): `reports\img\demo_warning.png` (an early-warning card with its cause set
     and gated proposal), `reports\img\demo_manual.png` (a card with z-offset manual advice), `reports\img\demo_modify.png`
     (the clipped Modify: the card or the "Last 50 events" row showing it). If a card type never appears in the three
     prints, say so in the issue comment; do not stage one.
   - Stop the dashboard (Ctrl+C in terminal 2) before the next print.
6. `uv run python scripts/run_demo.py report`
   Expected first three lines: `NFR-002: PASS|FAIL (...)`, `NFR-003: PASS|FAIL (...)`, `NFR-004: PASS (0 violations ...)`,
   then `wrote reports/demo.md`. PASS and FAIL are both valid results; NFR-004 FAIL means stop and post the report.
7. Optional, same runs: `uv run python scripts/eval_latency.py --runs <every db path in runs\demo\runs.json> --out reports\latency_runs.md`

## Success check
reports/demo.md has the NFR-002, NFR-003 and NFR-004 lines, one row per run (3 auto + 3 advisory), and the three
screenshots exist (or the comment says which card type never appeared).

## Send back
reports/demo.md, reports/img/demo_warning.png, demo_manual.png, demo_modify.png, runs/demo/plan.json and
runs/demo/runs.json (`git add -f`), reports/latency_runs.md if step 7 ran. Commit `T-0066: demo results (refs #66)`,
push, comment on #66 with the GPU name. Never commit runs/*/events.sqlite or frames.
