## Why
The 11-19 complete-data fine-tune scored test top-1 0.209 vs floor 0.254 (K2 FAIL, reports/cause_eval_full.md). The
dev side then found, on CPU (reports/recalibration*.md, reports/label_audit.md, reports/label_experiments.md):
1. **Bad labels.** 1,491 of the 1,522 single-cause `z_offset_low` images have z ≤ −1 mm, values the CAXTON README
   calls "incorrectly labelled and should be ignored". 17.5 % of single-cause frames sit inside CAXTON's own
   15-frame post-change gap. `scripts/clean_labels.py` writes `data/crops_clean.csv` without either (66,664 of 79,515
   crops; same crop files, same splits).
2. **Recipe.** lr 3e-4 on the whole net overfits a print's look by epoch 2–3 (train 0.68 vs calib 0.28); the
   RandomResizedCrop aspect jitter stretches bead width (the flow / z signal); `--max-per-print 100` gave ~9 k images
   per epoch; class-weighted CE optimises balanced accuracy while K2 scores plain top-1.
3. **Post-hoc recalibration on calib prints** alone (no GPU) lifts test top-1 0.209 → 0.294 (+4.1 pp over the floor,
   ECE 0.26 → 0.05). It is applied after every run below by `scripts/recalibrate.py`.

`scripts/train_cause.py` now has the v2 flags (all off by default, so old commands behave as before):
`--heads 4` (CAXTON's 4 × {low, good, high} heads, trains on multi rows too), `--lp-epochs` (LP-FT),
`--lr-backbone`, `--aug safe`, `--loss plain`, `--ema`, `--train-rows`.

## Block A — screen three recipes on folds 0 and 1 (≈ 3.5 h, ≈ 35 min per run)
Common flags (call them V2):
`--crops data\crops_clean.csv --lp-epochs 2 --lr-backbone 3e-5 --aug safe --loss plain --ema 0.999 --max-per-print 150 --epochs 12 --workers 8`

Run, in this order (each line twice: `--fold 0` then `--fold 1`):
1. A1 single 9-way head:
   `uv run python scripts/train_cause.py --fold 0 <V2> --out models\cause\v2\a1 --report reports\cause_fold0_v2_a1.md`
2. A2 four heads:
   `uv run python scripts/train_cause.py --fold 0 <V2> --heads 4 --out models\cause\v2\a2 --report reports\cause_fold0_v2_a2.md`
3. A3 margin-cleaned training rows:
   `uv run python scripts/train_cause.py --fold 0 <V2> --train-rows data\crops_margin.csv --out models\cause\v2\a3 --report reports\cause_fold0_v2_a3.md`

Each run ends `fold<k>: test top-1 ... · floor top-1 ...`; early stop usually at epoch 5–9. Then score them (CPU, 1 min):
```
foreach ($r in "a1","a2","a3") { uv run python scripts/recalibrate.py --model-dir models\cause\v2\$r --out-dir models\cause\v2\$r\recal --report reports\recalibration_v2_$r.md }
```
**Pre-registered pick:** the recipe with the highest "Mean cross-fit top-1 − floor" (last line of each
`reports\recalibration_v2_*.md`); if two are within 1.0 pp, the higher mean "cross-fit balanced". Write the winner and
the three numbers in the issue comment. Do not look at the `fold<k>.json` test numbers to choose.

## If it fails
- CUDA OOM: the script halves the batch itself. If it reaches 4 and still fails: `--batch 16 --workers 4`.
- Very slow epochs (> 600 s): `--workers 4` (Windows worker start-up), and note it in the comment.
- `crops not in ...` / missing crop files: re-run the 11-16 `build_crops.py` step; crops_clean.csv is a subset of
  crops.csv, so nothing new is needed.
- A3 trains on ~40 % fewer rows; if its early stop fires at epoch ≤ 3 every time, keep the result anyway (that is data).
