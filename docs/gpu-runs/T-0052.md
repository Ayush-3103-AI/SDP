# ⚠ GPU RUN — T-0052 Write the 2-hour soak test on replay + FakePrinter  (issue #52)
Written against commit: the `T-0052: ready for GPU run` commit (on top of ebe05ba)   ·   Est. time: 10–20 min   ·   Peak VRAM: 0 GB (CPU only)   ·   Needs data: no
Batch: no GPU, no weights, no data. It is here only because it is a long (`slow`) run that the dev laptop must not do. Run it on any team laptop, in any sitting, e.g. while a G1–G4 GPU job is training (it uses one CPU core and < 1 GB RAM).

## Prerequisites
- [ ] Setup A done on this laptop   - [ ] `git pull && uv sync` done
- [ ] `uv run python -c "import psutil; print(psutil.__version__)"` prints a version. psutil comes in with ultralytics; it is not yet declared in pyproject (the ticket asks for a dev dependency, but that needs a `uv lock` and this branch could not change the lock file).

## Steps
1. `uv run pytest tests/test_soak.py -q`
   Expected: `1 passed, 1 deselected` (the 40 s smoke version of the same harness)   Time: < 1 min
2. `uv run pytest -m slow tests/test_soak.py -q -rA -s 2>&1 | tee reports/soak_T-0052.txt`
   Expected: a `verdicts {...}  decisions {...}` line, then `1 passed, 1 deselected`   Time: 10–20 min
   (It writes 200 PNGs to a temp folder, then runs `Orchestrator.run` in auto mode for 72 000 frames = 2 simulated hours
   at 10 fps on a hand-driven clock, so frames are not slept. A seeded stub detector (seed 0) injects random
   non-critical defect bursts, a seeded random explainer gives 1–2 causes, and a background thread plays the operator:
   it answers about half the cards with apply/modify/reject/pause through `Store.insert_decision`, and lets the rest time
   out. RSS is sampled with psutil every 1 000 frames. Defects stop 100 s before the end so every open card times out.)

## Success check
- `reports/soak_T-0052.txt` ends with `1 passed` and has a `PASSED tests/test_soak.py::test_soak_2h` line.
- That means (NFR-008): no exception from the loop or the operator thread, RSS growth < 200 MB, and no pending event or
  unconsumed decision is left in the store. The `verdicts` line must show APPLY, PROPOSE and ESCALATE; the `decisions`
  line must show `timeout` and at least one of apply/modify/reject.

## Send back (exact list)
git add reports/soak_T-0052.txt
git commit -m "T-0052: soak run results (refs #52)"
git push

## If it fails
- `ModuleNotFoundError: psutil` → `uv sync` was not run, or ultralytics is missing. Run `uv sync`, then re-run step 2. Do not `pip install`.
- `AssertionError: RSS grew N MB` → a real leak. Send the log anyway; it is a real result. Note N on #52.
- `assert [...] == []` on `pending_events()` / `new_decisions()` → a card was left open. Send the log; the failing list is in it.
- `database is locked` → another process has the temp store open (an antivirus scan). Re-run step 2 once. If it repeats, send the log.
- The run takes more than 40 min → the disk is slow (each new PNG read is ~17 ms on Windows with Defender). Let it finish; time does not affect the result.
