## Steps
0. **Setup (5 min).** `git checkout main`, `git pull`, then bring in the dev branch:
   `git fetch origin claude/serene-fermi-gkkcx1` and `git merge --no-edit FETCH_HEAD`, then `uv sync` and
   `uv run pytest -q` (must pass). Note the GPU name for every issue comment.
1. **Regenerate the needed list (2 min).**
   `uv run python scripts/adapt_caxton.py --csv D:\caxton\caxton_dataset_filtered.csv --root D:\caxton --out data --per-print 500 --seed 0 --list-needed data\needed.txt`
   Expected: `kept: 79515`, and the per-cause counts match reports/data_audit.md. Check the hashes match the frozen
   split (they are recorded in logo.json): `Get-FileHash data\images.csv` must be
   `CB2C84B9BB6FEE207B720724682026AC160D22C3679DA68A51187E8587FD2EA6`. If not: stop, comment on #13.
2. **Fetch every missing image (≈ 1–2 h, unattended; disable sleep first).**
   `uv run python scripts/fetch_caxton_subset.py --needed data\needed.txt --root D:\caxton --workers 32`
   It skips images already on disk, so it fetches only the ~43 k missing ones. Expected last line `fetched N, failed 0`.
   If `failed` > 0, run the same command again (it retries only the failures). Use this script, not a custom helper.
3. **Rebuild the crops (≈ 10–20 min).**
   `uv run python scripts/build_crops.py --images data\images.csv --root D:\caxton --out data\crops --workers 4`
   Expected: `missing: 0` and `wrote data\crops.csv (79515 rows)`. If `missing` > 0: re-run step 2, then step 3.
   Then re-run the audit and floor so the reports describe the complete data:
   `uv run python scripts/audit_data.py` (expect line 1 `K1′: PASS` and "Missing crops: 0 of 79515") and
   `uv run python scripts/eval_cause.py --floor`.
4. **T-0013 re-run, fine-tune rung only (≈ 3–4 h, unattended).**
   `uv run python scripts/train_cause.py --all --max-per-print 100 --out models\cause\finetune_full --report reports\cause_fold0_full.md`
   `--max-per-print 100` keeps the per-epoch compute of the 11-11 run (≈ 10–12 k crops per epoch) while every epoch
   draws a fresh sample from all ~120 training prints. It was fixed before any result on the complete data.
   Then evaluate (copies the preds to the runtime folder; the 11-11 preds stay in git history):
   `uv run python scripts/eval_cause.py --model-dir models\cause\finetune_full --copy-to models\cause --out reports\cause_eval_full.md --errors reports\cause_errors_full.png`
   Line 1 is `K2: PASS (...)` or `K2: FAIL (...)`. **Either way, continue** (planned 2026-11-16 so the demo can run on a
   real model; the report labels the model with its K2 result). Exit 3 (`suspected leakage`) is the only stop: push and
   comment on #13. A human opens `reports\cause_errors_full.png` and writes one line of what they see into the
   "Risks" bullet of `reports\cause_eval_full.md`.
5. **Runtime model (≈ 45–60 min).** `uv run python scripts/train_cause.py --final --max-per-print 100`
   Expected: `final: ...`, `wrote tests\fixtures\cause_golden (8 crops)`. Then
   `uv run pytest tests/test_cause_artifact.py -q` → `3 passed`.
6. **Evaluations on the new preds (CPU, ≈ 20 min total).**
   T-0015: `uv run python scripts/eval_conformal.py` · T-0017: `uv run python scripts/eval_counterfactual.py` ·
   T-0063: `uv run python scripts/eval_proactive.py --crops data\crops.csv`. Each prints its NFR line first; PASS or
   FAIL are both valid results.
7. **T-0036 latency bench (GPU, ≈ 5 min).** docs/gpu-runs/T-0036.md steps 1–3. Put the GPU name at the top of the
   issue comment (the spec's S4 target names an RTX 3050).
8. **Human block (Krish or a teammate, in the browser; can run during step 4).**

   - **T-0043 pilot with a real person** per docs/gpu-runs/T-0043.md: someone who did not build the cards clicks
     every card and fills the surveys by hand (~30 min); then T-0044 (`docs/gpu-runs/T-0044.md`) regenerates

9. **T-0067 (optional, ≈ 5 min, after steps 5–6).** docs/gpu-runs/T-0067.md with the camera roll if it is downloaded.
